### Objetivo da sessão
Navegar os 12 sites de referência via MCP Playwright, coletar observações reais de UX e

### Problema encontrado: MCP Playwright + Chrome do sistema

**Sintoma:** Todas as tentativas de `mcp__playwright__browser_navigate` falharam.

**Erros em sequência:**

1. **Primeira tentativa (Chrome aberto):**
   - Erro: `Browser is already in use for /Users/mac/Library/Application Support/Google/Chrome`
   - Causa: Chrome do sistema estava aberto com o perfil padrão bloqueado

2. **Após fechar o Chrome:**
   - Erro: `DevTools remote debugging requires a non-default data directory`
   - Causa: O MCP lança o Chrome do sistema (`/Applications/Google Chrome.app`) com
     `--user-data-dir=/Users/mac/Library/Application Support/Google/Chrome` (perfil padrão).
     Desde o Chrome 115+, remote debugging com o perfil padrão do usuário é BLOQUEADO
     por segurança. O Chrome abre (visível nos processos do sistema) mas se recusa a
     aceitar o remote debugging pipe.

**Raiz do problema:** O `.mcp.json` do projeto (`/Users/mac/Desktop/SITE PAAPS/.mcp.json`)
está configurado com `--browser chromium`, mas o MCP está resolvendo `chromium` para o
Chrome do sistema, em vez do "Google Chrome for Testing" gerenciado pelo Playwright.

O "Google Chrome for Testing" correto está instalado em:
`/Users/mac/Library/Caches/ms-playwright/chromium-1228/chrome-mac-arm64/Google Chrome for Testing.app`

**Por que o MCP usa o Chrome errado:**
`@playwright/mcp@latest` baixa sua própria versão do Playwright como dependência.
Os navegadores instalados via `npx playwright install chromium` ficam em
`~/.cache/ms-playwright/` e são vinculados à versão LOCAL do Playwright (1.61.0).
O `@playwright/mcp@latest` tem uma versão INTERNA de Playwright que pode não encontrar
os browsers instalados localmente e faz fallback para o Chrome do sistema.

**Tentativas de correção realizadas:**
- `npx playwright install chromium` → instalou "Chrome Headless Shell 149" e "chromium-1228"
  mas não resolveu (MCP continua usando Chrome do sistema)
- `pkill -f "Google Chrome"` + remoção do `SingletonLock` → MCP simplesmente relança o Chrome

**Solução identificada (a implementar):**
Duas opções, ambas exigem reiniciar o Claude Code:
- **Opção A (preferida):** Atualizar o `.mcp.json` para passar o `--executable-path`
  apontando diretamente para o "Google Chrome for Testing":
  `"--executable-path", "/Users/mac/Library/Caches/ms-playwright/chromium-1228/chrome-mac-arm64/Google Chrome for Testing.app/Contents/MacOS/Google Chrome for Testing"`
- **Opção B:** Usar `--browser firefox` (requer `npx playwright install firefox`)

### Diagnóstico final
Causa raiz única: MCP iniciado sem `--isolated`, tentava reutilizar o perfil padrão
do Chrome do usuário (já aberto), que bloqueava a conexão. Não havia mismatch de versão —
`@playwright/mcp@0.0.76` usa `playwright@1.61.0-alpha` e o `chromium-1228` instalado em
`~/Library/Caches/ms-playwright` é da mesma versão (INSTALLATION_COMPLETE confirmado).

### Configuração final — .mcp.json
```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["--yes", "@playwright/mcp@0.0.76", "--browser=chrome", "--isolated"]
    }
  }
}
```

### Decisões
- `--browser=chrome`: usa Chrome já instalado → zero download, máxima compatibilidade
- `--isolated`: perfil temporário por sessão → sem conflito com Chrome aberto
- Versão pinada `@0.0.76` (não `@latest`): segurança contra supply chain e breaking changes
- `--headless` removido: browser visível, sem restrições de renderização
- `PLAYWRIGHT_BROWSERS_PATH` removido: desnecessário com --browser=chrome
- Nenhum download adicional necessário

### Segurança
- Versão pinada auditável
- Prompt injection documentado: ao navegar sites externos, Claude sinaliza qualquer
  tentativa de injeção de instrução via conteúdo de página

### Para ativar
Fechar e reabrir o Claude Code completamente. Nenhum comando extra.

## NOTA MANUAL — 15:35 — Playwright MCP: conflito de config global vs. projeto (modo extensão)

### Contexto
Mallu instalou a **extensão do Playwright MCP no Chrome** (modo `--extension`) para conseguir
navegar usando o Chrome real já logado (necessário p/ Instagram, que exige login). Mas a
navegação continuava falhando com `DevTools remote debugging requires a non-default data directory`.

### Causa raiz (a real, desta vez)
Existiam DOIS servidores MCP chamados `playwright`, em modos opostos:

| Onde | Modo | Efeito |
|---|---|---|
| `./.mcp.json` (projeto) | `--extension` ✅ | conecta no Chrome aberto via extensão (correto) |
| `~/.claude.json` → `projects/<este projeto>/mcpServers/playwright` | `--user-data-dir <perfil padrão>` ❌ | tenta LANÇAR um Chrome novo com o perfil padrão → bloqueado pelo Chrome 115+ |

O bloco no `~/.claude.json` **sobrepõe** o `.mcp.json` do projeto. Por isso o modo errado
vencia e a extensão instalada ficava inerte.

> Importante: as "soluções definitivas" anteriores deste mesmo dia (`--isolated`,
> `--browser=chrome`) editavam apenas o `.mcp.json` do projeto — e por isso NUNCA pegavam,
> porque o override global continuava ativo. O erro estava sempre no `~/.claude.json`.

### Correção aplicada
- Backup: `~/.claude.json.bak-<timestamp>`
- Reescrito o bloco global `playwright` para o mesmo modo extensão do projeto:
  ```json
  {
    "command": "npx",
    "args": ["--yes", "@playwright/mcp@0.0.76", "--extension"],
    "env": { "PLAYWRIGHT_MCP_EXTENSION_TOKEN": "[token removido do log por seguranca]" }
  }
  ```

### Para ativar (pendente — exige ação da Mallu)
1. Fechar e reabrir o Claude Code (MCP só recarrega na inicialização).
2. Manter o Chrome aberto com a extensão Playwright MCP ativa/autorizada.
3. Pedir de novo a navegação até `@paaps.brasil`.
